# 校准结果中文诊断报告

## 1. 结论摘要

当前仓库在 `conda` 的 `spice` 环境中已经具备完整可运行能力：

- `PySpice` smoke test 可通过
- 全量 `unittest` 可通过
- 当前 calibration artifacts 已完整生成

但从校准效果看，最终目标“42 个器件 x 6 个指标全部相对误差 `< 3%`”仍未达到。

当前已记录的基线结果为：

- 目标点数：`42`
- 当前默认策略下的 worst-case relative error：`5.103840e-02`
- 是否达成 `<3%`：`否`

同时保留一份原始对照基线：

- 原始基线 worst-case relative error：`5.116035e-02`

## 2. 当前误差格局

从 `artifacts/calibration_output/calibration_error_report.csv` 统计，当前 top 误差主要集中在以下点位：

1. `idoff_a @ (W=0.56, L=1.5)`：约 `5.104%`
2. `idoff_a @ (W=0.14, L=0.028)`：约 `5.096%`
3. `isoff_a @ (W=0.56, L=1.5)`：约 `4.890%`
4. `isoff_a @ (W=2.7, L=0.28)`：约 `4.389%`
5. `idoff_a @ (W=0.28, L=0.56)`：约 `4.357%`

按指标聚合后的 worst-case 为：

- `idoff_a`：`5.104%`
- `isoff_a`：`4.890%`
- `vtlin_v`：`4.300%`
- `vtsat_v`：`4.278%`
- `idlin_a`：`4.037%`
- `idsat_a`：`3.851%`

结论是：

- 漏电相关指标 `idoff_a` / `isoff_a` 仍然是首要瓶颈
- 但当前问题不只剩漏电项，`vtlin_v` / `vtsat_v` / `idsat_a` 也仍在 `4%+` 区间
- 即使只想把整体 worst-case 压到 `<3%`，也不能把优化完全收窄成只看漏电

## 3. 高误差尺寸分布

按尺寸点聚合后的 worst-case 前几名为：

1. `(0.56, 1.5)`：`5.104%`
2. `(0.14, 0.028)`：`5.096%`
3. `(2.7, 0.28)`：`4.389%`
4. `(0.28, 0.56)`：`4.357%`
5. `(0.28, 1.5)`：`4.330%`

这说明当前难点并不集中在单一尺寸边界：

- 既有最小尺寸角附近的困难点
- 也有中大尺寸区间的困难点
- 还包含长沟道 / 中沟道区域

因此，当前误差不像是单纯的“一个角点没搜到”，更像是现有局部搜索预算和参数表达能力共同限制了可达精度。

## 4. 敏感参数观察

从 `sensitivity_report.csv` 的绝对敏感度看，当前对 `idoff_a` / `isoff_a` 最敏感的参数主要包括：

- `ub`
- `toxe`
- `cit`
- `eta0`
- `vth0`
- `voff`

其中：

- `ub` 的数值敏感度显著高于其他参数
- `toxe` 也是漏电和阈值相关指标的共同关键参数
- `cit`、`eta0`、`vth0`、`voff` 对漏电与阈值都有较直接影响

这对后续优化意味着：

- 局部 refinement 不应该平均对待全部 14 个参数
- 漏电优先策略应优先放大上述参数在 focus / score 里的影响
- 如果后续要增加自由度，也应优先围绕这类对泄漏与阈值共同敏感的参数展开

## 5. 当前 pipeline 的真实行为

当前 `src/optimizer.py` 的主流程大致是：

1. 4 角点 `NSGA-II`
2. 从角点构造双线性初始曲面
3. 对 42 个目标点做局部微调
4. 用局部教师解做全局再拟合
5. 再输出最终参数和误差报表

但结合当前 artifacts，可以确认一个很关键的事实：

- `local_tuned_params.csv` 与 `refitted_global_params.csv` 在 42 个训练点上完全一致

这并不奇怪，因为当前 `src/global_refit.py` 使用的是反距离插值；在训练点本身，距离为 0，模型会直接返回该点教师参数。

这意味着：

- 当前全局 refit 在训练点上没有引入额外损失
- 当前 `calibrated_params.csv` / `calibrated_metrics.csv` 本质上反映的就是局部教师解质量
- 当前瓶颈不是“局部解很好，但 refit 又把它弄差了”
- 当前瓶颈更接近“局部优化本身还没把教师解压到足够低”

这一点很重要，因为它改变了后续优化优先级：

- 短期内更应该先提升搜索预算和局部 refinement 能力
- 而不是优先怀疑全局 refit 把误差重新拉高

## 6. 当前搜索预算的限制

当前实现里，默认搜索预算已经从最早的 bootstrap 配置提高到：

- 角点 `NSGA-II`：`pop_size=24`，`n_gen=8`
- 局部 Powell：`maxiter=36`，`maxfev=260`
- 局部 DE：`maxiter=20`，`popsize=10`

从工程角度看，这更像“先打通流程”的预算，而不是为了逼近 `<3%` 验收线而设置的预算。

在这种预算下，出现以下现象是合理的：

- 角点 Pareto 候选不够丰富
- 局部教师解仍停留在 `4%` 到 `5%` 区间
- 漏电项虽被识别为重点，但局部 refinement 对它的针对性仍不够强

## 7. 对“是否要重写遗传算法”的判断更新

基于当前 artifacts 和代码行为，现阶段不推荐先重写遗传算法。

原因有三点：

1. `pymoo` / `NSGA-II` 这一层已经正常工作，且 4 角点建模和 Pareto 导出链路是通的
2. 当前 evidence 更像“预算偏小 + 局部 refinement 不够针对”，而不是“算法框架本身错误”
3. 在现有框架下先提升预算、改良局部 score/focus，通常比自研新 GA 更低风险、更容易归因

更合理的顺序应当是：

1. 先提高预算
2. 再增强漏电优先 score/focus
3. 如果仍长期卡在 `4%` 到 `5%` 区间，再考虑问题特化的混合优化器

## 8. 建议的下一步动作

优先顺序建议如下：

1. 保留当前 `5.104%` 默认结果与 `5.116%` 原始基线作为双对照
2. 第一轮只提高 `NSGA-II`、Powell、DE 的搜索预算
3. 第二轮再引入漏电优先的 score / focus 策略
4. 每轮都重新跑 `spice` 环境下的全量测试和校准脚本
5. 以 fresh artifacts 比较 worst-case 是否实质下降，而不是只凭过程感受判断

## 9. 本轮策略实验结果

本轮新增策略接口后，实际跑了三组对照实验：

- 原始基线：`5.116035%`
- 只加预算 `budget_only`：`5.103840%`
- 轻度漏电加权 `leakage_mild`：`5.175249%`
- 更强漏电加权：`5.205551%`

结论很明确：

- 单纯增加搜索预算，虽然收益不大，但确实有小幅改善
- 额外对漏电项做加权后，结果反而变差
- 当前问题更像“整体搜索不够充分”，而不是“目标函数没有足够强调漏电”

因此，这一轮之后更合理的默认策略是：

- 保留更高的搜索预算
- 暂不把漏电偏置作为默认行为
- 仅把漏电加权保留为后续实验选项

## 10. 当前阶段判断

当前项目不是“还没建好”的状态，而是“已经建好可运行闭环，但仍处于性能压线阶段”。

从工程推进角度看，最值得做的不是推翻当前架构，而是：

- 用更充分的预算把现有链路跑透
- 用更有针对性的局部优先级继续压漏电项
- 在每轮实验后明确记录收益，防止进入无效调参
